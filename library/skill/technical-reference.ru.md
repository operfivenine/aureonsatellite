# Техническое описание и функциональность

[← Для разработчиков](../author-skill.ru.md) · [English](technical-reference.md)

**AURS Author Skill v0.7.0 — Early Beta (Frozen)** · цель **Aureon 0.24.5 v420** · **AURS API 1.1**.

## 1. Назначение и границы

Skill — инструкции, справочные файлы и офлайн-утилиты, помогающие Codex **спроектировать, написать, проверить и упаковать** декларативную аудиовизуальную сцену `.aurs`. В отличие от программного плагина, Skill не изменяет движок, интерфейс Aureon или поддержку функций во время выполнения. Результат работает только в пределах зарегистрированных возможностей конкретной редакции SDK.

Skill может применяться к новым сценам и **адресным изменениям существующих пакетов** (режим Preserve: не менять несвязанные подсистемы; сравнивать до/после).

## 2. Устройство AURS-пакета

`.aurs` — ZIP-контейнер. Типичное содержимое (зависит от renderer и зарегистрированных features):

```text
Theme.aurs
├── manifest.json       # Идентификатор, версия, renderer, entry и feature-зависимости
├── scene.json          # Параметры сцены, сигналы, поведение и ресурсы
├── preview.png         # Рендер-кадр, объявленный через scene.preview.v1
├── shaders/main.frag   # Основной fullscreen fragment, где это требуется
├── shaders/main.vert   # При подходящем Mesh/Hybrid контракте
├── shaders/background.frag  # При соответствующем Hybrid контракте
├── shaders/mp_*.frag   # Только для поддерживаемых multipass конфигураций
├── textures/...
└── meshes/...
```

Это **схематичное дерево**, а не универсальный минимальный валидный AURS. Обязательные пути/поля зависят от renderer и feature IDs. Следуйте `api/docs/package.ru.md` и актуальному `sdk/docs/PACKAGE_RU.md`. AURS запрещает произвольное исполнение вложенного Python; внешние генераторы ресурсов нужно оставлять за пределами пакета.

## 3. Архитектура художественного авторинга

### Stage A — Creative Direction

- Выбирает **workflow**, art, ресурсы, музыку и интерпретацию референсов **независимо**.
- Не позволяет смешивать Strict One-Shot с внутренней художественной переработкой.
- Требует определять художественный опыт до технической реализации.

### Stage B — Production Intelligence

- Проектирует фокус композиции, планы глубины, масштаб, конструктивную логику мира.
- Помогает распределять mesh, карты материалов, освещение, атмосферу, отражения и локальные процессы.
- Разрешает внутреннюю художественную проверку/исправления в `production_one_shot`.
- Режим Maximum не накладывает произвольных квот, но уважает SDK и GPU.

### Stage C — Motion & Music Intelligence

- Разделяет **движение наблюдателя**, **автономное изменение мира** и **аудиоуправляемые события**.
- Отличает `onset/attack`, длительную энергию и затухание; предлагает физически осмысленное применение музыкальных сигналов.
- При переменной скорости требует корректного накопления времени/фазы (интегратора), а не `time * speed(t)`.
- Для Reactive-First нужна проверка с реальной музыкой; статические значения сигналов не доказывают синхронизацию.

### Stage D — Multi-Keyframe Engine

- Выявляет соответствия объектов, масштаба, материалов и пространственных связей между упорядоченными кадрами.
- Отличает изменение мира от перемещения камеры.
- Выбирает процедурные переходы и оценивает **времена между референсными кадрами**, избегая слайд-шоу.
- `aurs_keyframe_brief.py` проверяет **только структуру необязательного sidecar JSON**. Он не анализирует картинки и не добавляет runtime API.

### Stage E — Integration & Artistic Trials

- Объединяет авторские правила, сохраняя приоритет пользовательского брифа и технического SDK.
- Разделяет тесты пакета, SDK, рендера, музыки, GPU и художественного впечатления.
- Содержит три готовых задания: CINE-01, PSY-01, KEY-01.

## 4. Выбор рендерера и функций

Точная поддержка сверяется с локальными реестрами `sdk/FEATURE_REGISTRY.json`, `sdk/SCHEMA_FIELDS.json` и `api/reference/`.

Доступные в документации направления — Fullscreen Fragment, Mesh, Hybrid Mesh и разрешённые расширения (например multipass, текстуры, реактивные контроли). **Нельзя считать совместимыми любые произвольные комбинации**. В `aurs_lookup.py` renderer указывается настоящим ID вида `scene.fullscreen_frag.v2`, а не человекочитаемой сокращённой строкой.

```powershell
cd aureon-aurs-author
py -3.13 -B scripts/aurs_lookup.py release
py -3.13 -B scripts/aurs_lookup.py renderers
py -3.13 -B scripts/aurs_lookup.py feature scene.preview.v1
py -3.13 -B scripts/aurs_lookup.py feature scene.multipass.experimental.v1 --renderer scene.fullscreen_frag.v2
py -3.13 -B scripts/aurs_lookup.py limits multipass
```

`aurs_lookup.py` — **read-only справочник**, не компилятор GLSL и не host validator.

## 5. Средства авторинга

| Инструмент | Назначение | Ограничение |
|---|---|---|
| `scripts/aurs_lookup.py` | Реестры релиза, функций, GLSL symbols, channels, limits | Только чтение справочников |
| `scripts/aurs_preflight.py` | Частичная статическая проверка каталога/архива | Не заменяет SDK parser |
| `scripts/aurs_pack.py` | Детерминированная упаковка `.aurs` | Не компилирует GLSL |
| `sdk/tools/validate_aurs.py` | Реальный parser выбранной версии SDK | Не рисует кадр и не измеряет GPU |
| `scripts/aurs_diff.py` | Сравнение двух пакетов/каталогов при scoped edit | Не доказывает эквивалентность поведения |
| `scripts/aurs_diagnose.py` | Диагностическая триаж-сводка с учётом симптомов/логов | Не запускает хост |
| `scripts/aurs_audit.py` | Статические сведения о ресурсах и графе рендера | Не предсказывает FPS/VRAM |
| `scripts/aurs_bench_compare.py` | Сравнение предоставленных реальных GPU-замеров | Не выполняет замеры |
| `scripts/aurs_keyframe_brief.py` | Проверка JSON-плана Multi-Keyframe | Не анализирует изображения |
| `scripts/aurs_trial_report.py` | Проверка структуры отчёта об испытании | Не устанавливает художественный PASS |
| `scripts/aurs_sync.py` | Локальная замена вспомогательной API-документации | Не скачивает и не удостоверяет источник |

Полные команды: Установка и CLI.

## 6. Артефакты и контракт выдачи

- Новая сцена: один законченный `.aurs`, `preview.png` из **реального кадра** при наличии задокументированного `scene.preview.v1`, короткий отчёт.
- Исходники редактируемой сцены: по запросу или по необходимости.
- По умолчанию **не создавать** MP4, GIF, контактные листы и тяжёлые визуальные отчёты.
- Любое заявление `HOST_RENDER`, `REAL_MUSIC`, `GPU_PERFORMANCE` обосновывать соответствующим запуском; если нет среды, `NOT_RUN`.

## 7. Известный недостаток Early Beta

Наличие оригинальных реактивных буферов и выразительной геометрии само по себе **не гарантирует зрительно активной психоделики**. В тесте PSY-01 пользователь просмотрел полный цикл и отверг результат из-за слабой воспринимаемой динамики. Это художественный FAIL данного испытания, а не доказательство неисправности API. Проект заморожен до возобновления.

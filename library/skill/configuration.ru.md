# Конфигурация AURS Author Skill v0.7.0 Early Beta

[← Для разработчиков](../author-skill.ru.md) · [English](configuration.md)

Настройки — это **текстовые указания Codex при авторинге**, а не исполняемый конфиг Aureon и не JSON-поля пакета. Можно писать человекочитаемые значения (`Production One-Shot`, `Psychedelic`) либо канонические идентификаторы из таблиц. **Все пять осей независимы**; явно заданный художественный бриф имеет приоритет над пресетами.

## 1. `workflow` — процесс создания

| Каноническое значение | Человеческое название | Художественные исправления до первого результата | Когда использовать |
|---|---|---|---|
| `adaptive` | Adaptive | По выбранному агентом процессу | Общие задачи, когда регламент не задан |
| `strict_one_shot` | Strict One-Shot | **Нет**. Технические исправления отдельно фиксируются | Честный тест первого творческого решения |
| `production_one_shot` | Production One-Shot | **Да**, если улучшения нужны для брифа | Один максимально зрелый результат для пользователя |
| `iterative` | Iterative / PASS | По согласованным с пользователем этапам | Контролируемые версии и сохранение принятых решений |

`Production One-Shot` — **одна выдача**, но не обязательно один внутренний черновик. Не выдавайте внутреннюю доработку за нетронутую первую попытку. В `Strict One-Shot` первый законченный творческий build сохраняется для оценки, косметическая/концептуальная переработка не допускается скрытно.

## 2. `art_direction` — художественная стратегия

| Значение | Приоритет | Не является обязательным |
|---|---|---|
| `auto` | Автовыбор по брифу | Универсальный шаблон |
| `cinematic_environmental` | Композиция, масштаб, конструктивная логика, материалы, свет, жизнь окружения | Глобальное морфирование мира |
| `psychedelic_reactive` | Пространственное ощущение, психоделические состояния, ритм, музыкальная причинность | Кристаллический тоннель, симметрия, вспышки в каждом кадре |
| `transformative_procedural` | Связанная процедура видимых изменений структур и их взаимоотношений | Обязательное разрушение или фиксированное число фаз |
| `hybrid` | Осмысленное сочетание художественных стратегий | Требование применять все техники сразу |

## 3. `resource_intent` — бюджет ресурсов

| Значение | Поведение |
|---|---|
| `balanced` *(по умолчанию)* | Соразмерность художественного качества и стоимости рендера |
| `efficient` | Компактная реализация без сознательной потери основных художественных целей |
| `maximum` | Отсутствие **произвольных** ограничений на текстуры/меши/проходы; ресурсы выделяются по видимому вкладу |
| `custom` | Ограничения диктует пользователь: например, платформа, целевое разрешение, измеряемый GPU-бюджет или требования к пакетированию |

`maximum` **не обязывает** выпускать `.aurs` тяжелее 100 МБ, включать multipass или выбирать Hybrid. Приоритет — заметное качество в пределах **документированного SDK и реального GPU-бюджета**. Не обещать FPS без измерения.

## 4. `music_intent` — отношение к музыке

| Значение | Поведение |
|---|---|
| `adaptive` *(по умолчанию)* | Агент выбирает подходящую реакцию по художественному заданию |
| `reactive_first` | Музыкальная причинность влияет на архитектуру движения и событий: атаки, устойчивую энергию, затухание, транспорт |
| `ambient` | Спокойная/локальная реактивность, допустимо минимальное движение |
| `custom` | Пользователь задаёт конкретные принципы реактивности |

У `reactive_first` нет обязательного маппинга bass/mid/high и нет универсального BPM-часового механизма. Для доказанного попадания в музыку нужен **реальный трек** и наблюдение в Aureon; проверка функций шейдера недостаточна.

## 5. `reference_mode` — визуальные исходники

| Значение | Что передать | Как трактуется |
|---|---|---|
| `none` | Только бриф | Codex сам разрабатывает визуальный язык |
| `single` | Один референс | Внешний вид, композиция, эстетика; не обязательно буквальная копия |
| `reference_set` | Несколько независимых референсов | Настроение, объекты, материалы, разные ракурсы; **не** автоматическая временная последовательность |
| `multi_keyframe` | Упорядоченные изображения + порядок/таймкоды (если нужны) | Временные состояния **одного мира**, поддержание непрерывности и построение промежуточных состояний |

Multi-Keyframe — **не** четыре отдельные генерации, не crossfade картинок и не фича `scene.multi_keyframe`. При четырёх ракурсах одной станции агент не должен без причины выдумывать изменение топологии. Необязательный `keyframe_intent.json` — authoring-sidecar вне `.aurs`.

## 6. Выдача и проверки

**Default:** один `.aurs` + встроенный **реальный** `preview.png` (если целевой SDK поддерживает `scene.preview.v1`) + короткий отчёт. Редактируемые исходники — по запросу. **MP4 / GIF / контактные листы не создавать по умолчанию**. Попросите различать `STATIC_PREFLIGHT`, `SDK_PARSER`, `HOST_RENDER`, `REAL_MUSIC`, `GPU_PERFORMANCE`, `USER_ART`. Для невозможных тестов писать `NOT_RUN`.

## 7. Сочетания

| Задача | `workflow` | `art_direction` | `resource_intent` | `music_intent` | `reference_mode` |
|---|---|---|---|---|---|
| Кинематографичный мир | `production_one_shot` | `cinematic_environmental` | `maximum` | `ambient` / `adaptive` | `none` / `single` |
| Психоделическая аудиовизуальная сцена | `production_one_shot` | `psychedelic_reactive` | `maximum` | `reactive_first` | `none` |
| Преобразование по референсам | `production_one_shot` | `transformative_procedural` | `maximum` | `adaptive` | `multi_keyframe` |
| Тест качества с первой попытки | `strict_one_shot` | Любой | Любой | Любой | Любой |
| Доработка сцены | `iterative` | По существующей сцене | По задаче | По задаче | По задаче |

**Примечание:** высокая инженерная сложность не доказывает художественную выразительность. В Early Beta испытание `PSY-01` не прошло художественную приёмку.

## 8. Минимальная карточка

```text
$aureon-aurs-author
Workflow: Production One-Shot
Art Direction: Cinematic / Environmental
Production Budget: Maximum
Music Direction: Ambient
References: Single

Brief: [что создаём, ключевой образ, настроение, движение]
Delivery: one .aurs with real preview.png + brief report; NO VIDEO
```

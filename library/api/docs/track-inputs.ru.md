# Данные текущего трека

[← API](../README.ru.md) · [English](track-inputs.md)

`scene.track_palette.experimental.v1` публикует `u_track_palette0` и `u_track_palette1`
типа vec3: шесть конечных неотрицательных весов с суммой 1. Начальное состояние соответствует
первой бирюзовой схеме, последовательность идёт по кругу в пределах сеанса.
Смена трека и повтор того же файла после конца переключают целевую схему;
pause/seek/повторный анализ этого не делают. Переход 2.4 с продолжается от текущей смеси
при быстром Next и переживает пересоздание GL. Автор определяет цвета по полученным весам.

`scene.track_text.experimental.v1` доступен в Hybrid: корневое `track_text` содержит
только `sampler` с именем `u_tex_...`. Хост рисует текущий заголовок в read-only RGBA8
2048×128; пакет читает текстуру, а не строку metadata или путь файла.
Unicode формируется Qt; управляющие символы убираются, заголовок ограничен 160 символами,
длинный текст визуально сокращается многоточием. Пустой текст очищает атлас.

Дополнительно `u_track_text_metrics` vec4: ширина/2048, флаг непустого текста, 1/2048, 1/128;
`u_track_text_age` float — время с изменения заголовка. Повторная отрисовка одинакового
заголовка не создаёт новую загрузку текстуры каждый кадр. Текст занимает отдельный sampler.
Имя должно быть свободно от image/material/audio/buffer bindings.

Эти возможности независимы: палитра не содержит текст; текст не предоставляет произвольные
поля тегов, Python API, файловую систему или сетевой доступ. Не вводить свои song_title
JSON-поля или строковые GLSL uniforms: они не являются этим контрактом.
